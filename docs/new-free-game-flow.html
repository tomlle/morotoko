新作無料ゲームは
どう判定される？

Steamの「無料」表示をそのまま投稿するのではありません。新着一覧、商品詳細、過去の観測記録を順番に照合し、導入後に初めて現れた常時無料のゲームだけをXへ送ります。

ひとことで言うと 「初めて見つけたApp ID」かつ「ゲーム本体」かつ「本当に常時無料」なら投稿

昔からある無料ゲームは、初回の基準作成で投稿対象から外します。

通常実行の全体フロー

3時間ごと

1前回の正常走査時刻と観測済みApp IDを読む

「どこまで確認済みか」と「以前に見たゲームか」を、リポジトリ内の状態ファイルから復元します。

2Steamの無料ゲームを発売日の新しい順に取得

Released_DESC・maxprice=free・ゲームカテゴリで検索します。1ページ50件ずつ取得します。

3前回時刻より7日前までページをさかのぼる

Steamへの掲載遅れ、日付境界、1ページを超える新作に備えた重複確認です。安全上限は5,000件です。

4このApp IDは以前に観測済み？

タイトルではなくSteamのApp IDで判定するため、同名ゲームやタイトル変更の影響を受けません。

はい：観測済み

原則として再投稿しない

検索欄から一度消えて再登場しても、同じApp IDは新作に戻りません。投稿待ちの案件だけは再検証します。

いいえ：初観測

Steamの商品詳細を取得

検索結果だけでは誤判定しやすいため、appdetails APIで中身を確認します。

53つの条件をすべて満たす？

  • type === "game"
    ゲーム本体
  • is_free === true
    常時無料
  • 元価格が0円
    有料商品ではない
1つでも不一致

対象外

デモ、DLC、有料ゲーム、別の無料ライセンスなどは「新作無料ゲーム」として投稿しません。

すべて一致

新しい常時無料ゲームとして登録

App IDを観測済みにし、投稿状態をpendingとして保存します。

6Buffer経由でXへ投稿

「新作無料ゲーム」としてタイトル、説明、Steam URLを送信します。受付結果も保存し、失敗や不明状態は次回以降に再確認します。

最初の1回だけは投稿しない

過去作の大量投稿を防止
機能導入直後

まだ「以前から存在したゲーム」と「これから追加されるゲーム」の境界がありません。

→
最初の正常な検索

見つけた全App IDを基準として保存します。詳細取得に失敗したIDも基準へ含めます。

→
2回目以降

その基準にないApp IDだけを「新しく追加された候補」として詳しく判定します。

例外と対象範囲

ここが誤解されやすいポイント

検索や詳細取得が失敗したら

前回の正常走査時刻を進めません。次の実行で同じ期間を再取得するため、一時障害による取りこぼしを防ぎます。

今回の「新作」の意味

Steamの発売日順の無料ゲーム検索へ、新しいApp IDとして現れたゲームを指します。

現在は検出しないもの

すでに発売済みの有料ゲームが、後日価格を変更して常時無料になったケースは対象外です。

具体例

App IDで考える

投稿される

  • 前回まで存在しなかったApp ID
  • 商品種別がゲーム本体
  • Steam詳細で常時無料

投稿されない

  • 初回の基準に含まれた過去作
  • 一度観測済みのApp ID
  • デモ、DLC、有料ゲーム

次回へ持ち越す

  • 検索結果の形式が壊れている
  • 必要ページを最後まで取れない
  • 候補の商品詳細を取得できない
